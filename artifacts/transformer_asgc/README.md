# Transformer ASGC evidence bundles

Frozen outputs of `notebooks/transformer_asgc_cuda.ipynb` (GPT, Tiny Shakespeare, one Tesla T4
plus three CPU workers). These files are committed so the §5b numbers in
[`findings_for_report.md`](../../findings_for_report.md) are auditable without a GPU rerun.

| run | eval cadence | role |
|---|---|---|
| `run_20261102_104333` | every 20 accepted updates, plus final | headline §5b table (F13–F17) |
| `run_20261102_095934` | time-based every 12 s, plus final | prior run used only for the cross-run caveats in F15/F16 |

Both runs used seed 0, a 200-update budget, 32 Mbps up-link / 128 Mbps down-link, and repo commit
`fcdfecdb6e205399211bf18e665eceb6f4489013`.

## Contents

`run_20261102_104333/`:

- `FINDINGS_TRANSFORMER.md` — generated report for that run.
- `results.json`, `summary_aggregate.csv`, `summary_per_seed.csv` — aggregate metrics.
- `eval_curves.csv`, `push_events.csv`, `monitor_samples.csv`, `worker_summary.csv`,
  `checkpoint_eval.csv` — raw telemetry and checkpoint-only re-evaluation.
- `plots/*.png` — nine figures (loss vs updates, final accuracy, wall-clock, wire bytes,
  time-to-target, rejections, adaptive trajectory, bandwidth-quality trade-off, accuracy vs updates).
- `config.json`, `environment.json` — reproducibility metadata.

`run_20261102_095934/` contains only the summary, config, environment, and findings needed for the
cross-run comparison; its full telemetry and plots are not archived.

## What is not archived

The `checkpoints/` directories (~28.5 MB per run) are excluded to keep the repository small. They can
be regenerated by re-running the notebook; every metric they produced is already in
`checkpoint_eval.csv`.

## Caveats

- Wall-clock and bandwidth are simulated; these are not measurements of a real network.
- Single seed per arm. The two runs differ in eval cadence, so cross-run deltas mix seed, protocol,
  and scheduling effects.
- Accuracy is teacher-forced next-token top-1/top-5 over 10,240 held-out tokens, not generation
  quality.
